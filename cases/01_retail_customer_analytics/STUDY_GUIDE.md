# CASE 01 분석 용어 학습 가이드

이 문서는 `Retail Customer & Revenue Analytics`를 진행하면서 사용하는 분석 용어를 쉬운 말로 설명한다. 정의를 외우기보다 **무엇을 세는지, 어떤 데이터를 빼는지, 그 결과로 어떤 판단을 할 수 있는지**를 이해하는 것이 목적이다.

## 1. 먼저 알아야 할 분석 흐름

### Business Question

분석으로 답하려는 사업상의 질문이다. 단순히 "매출을 분석한다"가 아니라, 분석 결과를 보고 누가 어떤 행동을 결정할지를 포함해야 한다.

- 쉬운 뜻: 이 분석을 왜 하는가?
- CASE 01 예시: CRM 담당자가 어떤 고객에게 유지 또는 재활성화 활동을 우선할지 결정한다.
- 주의: 데이터에 없는 원가나 광고비까지 답하려고 하면 안 된다.

### SQL Extraction

원천 데이터에서 분석에 필요한 행과 열을 SQL로 조회하고 기본 집계를 확인하는 단계다.

- 쉬운 뜻: 분석할 데이터를 데이터베이스에서 정확히 꺼내는 과정
- CASE 01 예시: 두 연도 데이터를 합친 테이블에서 시트별 행 수, 고객 ID 결측 수, 거래 기간을 조회한다.
- 주의: 이 단계에서 근거 없이 결측치나 반품을 삭제하면 이후 결과를 재현하기 어렵다.

### Data Quality Check

데이터가 분석에 사용할 만큼 믿을 만한지 확인하는 과정이다.

- 확인 대상: 결측치, 중복 후보, 잘못된 타입, 불가능한 값, 취소·반품, 날짜 범위
- CASE 01 예시: 음수 수량이 실제 취소 송장과 일치하는지 확인한다.
- 주의: 이상해 보이는 값이 반드시 오류인 것은 아니다. 대량 주문이나 조정 거래일 수도 있다.

### EDA (Exploratory Data Analysis)

정식 결론을 내리기 전에 분포, 추세, 관계를 폭넓게 탐색하는 분석이다. 한국어로는 탐색적 데이터 분석이라고 한다.

- 쉬운 뜻: 데이터가 어떤 모습인지 여러 각도에서 살펴보는 과정
- CASE 01 예시: 월별 매출 추세, 국가별 주문 수, 고객별 구매금액 분포를 확인한다.
- 주의: EDA에서 발견한 패턴만으로 원인과 결과를 단정할 수 없다.

### KPI (Key Performance Indicator)

사업의 상태나 목표 달성 정도를 판단하기 위해 지속적으로 보는 핵심 지표다.

- 쉬운 뜻: 의사결정자가 정기적으로 확인할 핵심 숫자
- CASE 01 후보: 순매출, 주문 수, 평균 주문금액, 재구매율, 취소·반품률
- 주의: 계산식, 기간, 분모, 포함·제외 조건이 없으면 같은 이름의 KPI도 서로 다른 숫자가 된다.

### Visualization

검증된 숫자를 의사결정자가 한 장으로 볼 수 있게 그리는 단계다. 이 프로젝트에서는 matplotlib로 PNG를 만들고 Jupyter 노트북에 같은 화면을 남긴다.

- 쉬운 뜻: 핵심 숫자와 우선순위를 한 페이지에 모아 보여 주는 그림
- CASE 01 예시: `notebooks/05_decision_dashboard.ipynb`, `evidence/dashboard/01_one_page_decision.png`
- 주의: 차트 도구를 바꿔 날짜를 최신으로 바꾸거나, 데이터에 없는 예측을 넣지 않는다.

### Insight & Action

검증된 사실을 실행 가능한 제안으로 바꾸는 단계다. 숫자의 근거는 앞 단계에 두고, 할 수 없는 말은 `Limitation`으로 적는다.

- CASE 01 예시: [`INSIGHTS.md`](./INSIGHTS.md)
- 주의: 상관을 인과로 바꾸거나, 없는 원가로 이익을 단정하지 않는다.

## 2. 데이터 구조와 SQL 용어

### PostgreSQL, DBeaver, SQL의 차이

| 용어 | 쉬운 설명 |
| --- | --- |
| PostgreSQL | 데이터를 저장하고 계산하는 데이터베이스 시스템 |
| DBeaver | PostgreSQL에 접속해 테이블을 보고 SQL을 실행하는 프로그램 |
| SQL | 데이터베이스에 조회와 집계를 요청하는 언어 |

DBeaver가 데이터를 저장하는 것은 아니다. DBeaver에서 작성한 SQL을 PostgreSQL이 실행한다.

### Schema와 Table

- `Schema`: 데이터베이스 안에서 관련 테이블을 묶는 폴더와 비슷한 논리적 공간
- `Table`: 행과 열로 데이터를 저장하는 구조
- CASE 01 예시: `retail`이 schema이고 `retail.online_retail_raw`가 table이다.

### Raw Data

분석가가 임의로 값을 바꾸기 전의 원천 데이터다. 나중에 문제가 생겼을 때 처음 상태로 돌아갈 수 있도록 보존해야 한다.

### Source of Truth

여러 파일이나 테이블의 숫자가 다를 때 기준으로 삼기로 합의한 공식 데이터 원천이다.

- CASE 01 기준: 두 Excel 시트를 변경 없이 합쳐 적재한 `retail.online_retail_raw`
- 주의: 정제 데이터는 분석 목적에 따라 행이 제외되므로 원천 데이터와 역할이 다르다.

### Grain

데이터 한 행이 무엇을 의미하는지를 말한다. 분석에서 가장 먼저 확인해야 할 개념 중 하나다.

- CASE 01의 한 행: 주문 전체가 아니라 송장 안의 상품 한 줄(`invoice line item`)
- 예시: 한 주문에 상품이 4종류 있으면 주문은 1건이지만 데이터는 4행일 수 있다.
- 주의: 행 수를 주문 수로 사용하면 주문을 과대 계산하게 된다. 주문 수는 보통 고유한 송장 번호를 센다.

### Primary Key와 Candidate Key

- `Primary Key`: 각 행을 유일하게 구분하는 공식 식별자
- `Candidate Key`: 여러 컬럼을 조합해 유일한 식별자 후보로 검토하는 값
- CASE 01 제한: 원본에 거래 라인 ID가 없으므로 완전히 같은 행도 정상 반복 입력인지 중복 오류인지 확정하기 어렵다.

### NULL과 Missing Value

값이 0이라는 뜻이 아니라 값이 기록되지 않았다는 뜻이다.

- `Customer ID = NULL`: 고객을 식별할 수 없음
- `Quantity = 0`: 수량 값이 실제로 0이라고 기록됨
- 주의: NULL 고객을 `0`이나 하나의 가상 ID로 채우면 서로 다른 익명 고객이 한 사람으로 합쳐진다.

### DISTINCT와 Aggregation

- `DISTINCT`: 중복을 제외한 서로 다른 값을 셈
- `Aggregation`: 여러 행을 합계, 평균, 개수 등으로 요약함
- 예시: `COUNT(DISTINCT invoice)`는 고유 송장 수, `SUM(quantity * price)`는 거래금액 합계다.

### View

SQL 조회문을 이름 붙여 저장한 가상 테이블이다. 원천 데이터를 복사하지 않고도 분석용 컬럼과 조건을 일관되게 제공할 수 있다.

### Data Contract

데이터의 행 단위, 컬럼, 타입, 결측 허용 여부, 필터 조건을 미리 합의한 규칙이다. SQL과 Python이 같은 의미의 데이터를 사용하도록 해준다.

## 3. 품질 관리 용어

### Missingness 또는 Completeness

필요한 값이 얼마나 채워져 있는지 보는 품질 기준이다.

```text
결측률 = 결측 행 수 / 전체 행 수 × 100
```

고객 ID 결측 거래는 전체 매출 탐색에는 사용할 수 있지만 고객별 재구매나 RFM 분석에는 사용할 수 없다.

### Duplicate

같은 데이터가 두 번 이상 존재하는 상태다. 완전히 같은 행뿐 아니라 업무상 같은 거래가 다른 형태로 반복된 경우도 포함할 수 있다.

- 주의: CASE 01에는 고유 라인 ID가 없으므로 완전 동일 행을 발견해도 자동 삭제하지 않고 먼저 규모와 패턴을 확인한다.

### Outlier

대부분의 값에서 크게 벗어난 값이다. 한국어로 이상치라고 한다.

- CASE 01 예시: 매우 큰 주문 수량이나 단가
- 주의: 이상치는 오류일 수도 있지만 실제 대량 주문일 수도 있다. 통계적 기준과 업무 맥락을 함께 확인해야 한다.

### Validity

값이 정해진 형식이나 업무 규칙을 만족하는지 확인하는 품질 기준이다.

- 예시: 수량이 숫자인지, 거래 날짜가 분석 기간에 포함되는지 확인한다.

### Reconciliation

두 단계나 두 시스템의 숫자가 일치하는지 대사하는 작업이다.

- CASE 01 예시: 두 Excel 시트의 행 수 합계와 PostgreSQL 적재 후 행 수가 같은지 확인한다.

### Cancellation과 Return

- `Cancellation`: 주문이나 거래를 취소한 것
- `Return`: 구매한 상품을 반품한 것
- CASE 01에서는 `Invoice`가 `C`로 시작하거나 `Quantity < 0`인 행을 취소·반품 후보로 본다.
- 주의: 두 조건이 항상 일치한다고 가정하지 않고 불일치 행을 따로 점검한다.

## 4. 매출과 주문 지표

### Total Revenue

거래 한 행의 수량과 단가를 곱한 금액이다.

```text
Total_Revenue = Quantity × Price
```

음수 수량인 반품 행은 `Total_Revenue`도 음수가 된다.

### Gross Sales Revenue

완료된 양수 판매만 합산한 매출이다. 취소·반품의 음수 금액을 차감하기 전 판매 규모를 보여준다.

```text
Gross Sales Revenue = SUM(Total_Revenue WHERE Quantity > 0 AND Price > 0 AND 정상 판매)
```

### Return Value

취소·반품으로 감소한 금액의 절댓값이다. 보고서에서 양수 금액으로 표현하면 손실 규모를 읽기 쉽다.

### Net Revenue

양수 판매금액에서 취소·반품 금액을 반영한 금액이다.

```text
Net Revenue = Gross Sales Revenue - Return Value
```

원본 데이터만으로 모든 반품을 최초 구매와 정확하게 연결할 수 있는지는 별도 검증이 필요하다.

### Order Count

거래 행 수가 아니라 고유한 완료 송장 번호의 개수다.

```text
Order Count = COUNT(DISTINCT completed invoice)
```

### AOV (Average Order Value)

주문 한 건당 평균 구매금액이다.

```text
AOV = Gross Sales Revenue / Completed Order Count
```

행당 평균 금액과 혼동하지 않아야 한다.

### Cancellation/Return Rate

분모에 따라 의미가 달라진다.

- 주문 기준 취소율: 취소 송장 수 / 전체 송장 수
- 거래 라인 기준 비율: 취소·반품 행 수 / 전체 거래 행 수
- 금액 기준 비율: 반품 금액 / 양수 판매금액

따라서 보고서에는 어떤 기준의 비율인지 반드시 표시한다.

## 5. 고객 분석 용어

### Customer Segment

비슷한 특징이나 행동을 가진 고객을 묶은 그룹이다. 한국어로 고객 세그먼트 또는 고객군이라고 한다.

- 쉬운 뜻: 모든 고객을 똑같이 보지 않고 공통된 행동에 따라 나눈 집단
- CASE 01 예시: 최근에도 자주 구매하는 고가치 고객, 과거에는 많이 샀지만 최근 구매가 없는 고객
- 목적: 그룹마다 다른 유지, 재활성화, 서비스 전략을 적용하기 위함
- 주의: 세그먼트는 분석 규칙으로 만든 분류이며 고객의 성격이나 구매 이유를 직접 증명하지 않는다.

### RFM Analysis

고객 행동을 세 가지 기준으로 요약해 세그먼트를 만드는 방법이다.

| 요소 | 의미 | CASE 01 계산 방향 | 좋은 값의 방향 |
| --- | --- | --- | --- |
| Recency | 마지막 구매가 얼마나 최근인가 | 기준일 - 마지막 완료 구매일 | 낮을수록 최근 구매 |
| Frequency | 얼마나 자주 구매했는가 | 고유 완료 송장 수 | 높을수록 자주 구매 |
| Monetary | 얼마를 구매했는가 | 완료 구매금액 합계 | 높을수록 구매금액 큼 |

RFM 점수의 구간과 세그먼트 이름은 데이터 분포를 확인한 뒤 확정한다.

### Cohort

같은 시점에 처음 구매한 고객을 하나의 집단으로 묶은 것이다.

- 예시: 2010년 3월 첫 구매 고객 코호트
- 목적: 유입 시기가 다른 고객들이 이후 몇 개월 동안 다시 구매하는지 비교한다.

### Retention Rate

처음 구매한 고객 중 이후 기간에도 다시 구매한 고객의 비율이다.

```text
n개월차 유지율 = n개월차에 재구매한 코호트 고객 수 / 최초 코호트 고객 수 × 100
```

`Customer ID`가 없는 거래는 같은 고객의 재구매 여부를 확인할 수 없어 유지율 계산에서 제외한다.

### Segment와 Cohort의 차이

- `Segment`: 행동이나 가치가 비슷한 고객을 묶음
- `Cohort`: 시작 시점이나 공통 경험이 같은 고객을 묶음

한 고객은 "고가치 세그먼트"이면서 동시에 "2010년 3월 신규 고객 코호트"에 속할 수 있다.

### Reactivation

한동안 구매하지 않던 고객이 다시 구매하도록 유도하는 활동이다. 최근 구매가 오래됐지만 과거 구매 가치가 높았던 고객이 후보가 될 수 있다.

### Customer Lifetime Value (CLV)

고객이 관계를 유지하는 동안 가져올 것으로 기대되는 전체 가치를 뜻한다. CASE 01 데이터에는 원가와 충분한 미래 정보가 없으므로 정교한 수익 기반 CLV를 확정적으로 계산하기 어렵다. 과거 누적 구매금액은 CLV 자체가 아니라 고객 가치의 대용 지표다.

## 6. 해석할 때 지켜야 할 원칙

### Correlation Is Not Causation

두 값이 함께 움직인다고 해서 하나가 다른 하나의 원인이라는 뜻은 아니다. 예를 들어 특정 국가의 평균 주문금액이 높아도 국가 자체가 높은 구매를 발생시켰다고 단정할 수 없다.

### Statistical Significance

관찰된 차이가 우연만으로 나타났다고 보기 어려운지를 통계적으로 평가하는 개념이다. 통계적으로 유의하더라도 실제 사업 효과가 작을 수 있으므로 효과 크기도 함께 봐야 한다.

### Limitation

데이터 때문에 답할 수 없는 범위를 명확히 적는 것이다. CASE 01은 오래된 역사 데이터이며 원가, 광고, 배송, 고객 인구통계가 없으므로 현재 시장 전망, 이익, 마케팅 인과효과를 직접 설명할 수 없다.

### Reproducibility

다른 사람이 같은 원본, 코드, 실행 순서를 사용해 같은 결과를 얻을 수 있는 성질이다. 경로, 패키지, SQL, 필터 조건, 지표 정의를 문서화해야 한다.

## 7. 권장 학습 순서

1. 먼저 `grain`, `NULL`, `DISTINCT`, `aggregation`을 이해한다.
2. 다음으로 주문 수, 양수 매출, 반품 금액, 순매출의 차이를 익힌다.
3. 고객 ID 결측이 고객 분석에 미치는 영향을 이해한다.
4. RFM의 세 요소와 segment·cohort의 차이를 익힌다.
5. 마지막으로 KPI 정의와 분석의 한계가 왜 필요한지 확인한다.

용어를 공부할 때는 항상 "이 지표의 한 행은 무엇인가?", "분모는 무엇인가?", "어떤 거래가 제외되는가?"를 함께 질문한다.
